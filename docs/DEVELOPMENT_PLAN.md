## 阶段 1：工程和静态原型

目标：建立工程结构和主要界面。

- 创建核心 Swift 包。
- 创建 iOS App target。
- 创建 watchOS App target。
- 首页、骑行页、好友页、历史页。

验收：

- iOS App 能在模拟器启动。
- Watch App 能在模拟器启动。
- `swift test` 通过。

## 阶段 2：骑行记录 MVP

目标：手机可以记录一条真实骑行。

- CoreLocation 权限申请。
- 开始/暂停/继续/结束。
- 后台位置更新。
- 轨迹点存储。
- 地图轨迹展示。
- 统计距离、速度、时长。
- 本地 JSON 持久化。
- GPX 导出。

验收：

- 锁屏后能继续记录。
- 骑行结束后能看到路线和统计。
- 关闭 App 后能重新读取历史记录。
- 可从骑行详情生成并分享 GPX 文件。

## 阶段 3：Apple Watch MVP

- 实时心率和距离。

- 保存 workout 到 Apple 健康。

验收：

- Watch 真机上能开始 workout。

前置条件：

- iOS App 与 Watch App 使用同一个开发团队签名。
- HealthKit capability 已开启。

## 阶段 4：语音 MVP

目标：好友小队可实时语音。

- 接入 LiveKit Swift SDK。
- 后端生成 room token。
- 加入/退出房间。
- 静音/解除静音。
- 后台音频。
- 自动重连。

验收：

- 两台 iPhone 真机能语音。
- 锁屏、切后台、网络切换后能恢复。

中间件：

- LiveKit Cloud 或自建 LiveKit。
- 后端 token endpoint。

当前已完成：

- 后端 LiveKit token endpoint 骨架。
- iOS token 请求客户端。
- Xcode target 已添加 LiveKit Swift SDK 2.x。
- `VoiceRoomClient` 已使用 LiveKit `Room` 真实连接。
- 已实现加入、退出、静音、成员状态和重连状态。

待真机验收：

- 两台 iPhone 同房间通话。
- 锁屏、切后台、Wi-Fi/蜂窝网络切换后的语音恢复。

## 阶段 5：账号、好友和云同步

目标：可小规模内测。

- Apple 登录。
- 好友申请和同意。
- 小队管理。
- 骑行记录上传。
- 历史记录云同步。
- APNs 推送。

当前已完成：

- 设备绑定的访客账户，可原地升级绑定 Apple ID。
- 服务端验证 Apple JWT 签名、Bundle ID、有效期和 nonce。
- iOS 会话保存在 Keychain，服务端会话默认 30 天过期并支持退出。
- 用户中心、昵称编辑和 8 位好友码。
- 好友申请发送、接受、拒绝和好友列表。
- NAS JSON 数据持久化与 Docker 数据卷。
- 登录账户作为 LiveKit 语音身份，匿名 token 请求已关闭。
- 语音房间强制校验双方好友关系，并支持在语音页选择通话好友。
- 小队创建、好友邀请、成员移出/退出、解散和小队多人语音。
- 完成骑行后自动上传；启动、手动刷新时同步账号历史；支持云端删除。
- 公网接口已增加全局及登录/语音专项限流。
- APNs Sandbox 与 Production 双通道已接入：Debug 和 TestFlight/App Store 自动使用
  对应环境，iOS 自动绑定/解绑 device token，失效 token 会自动清理。
- 服务端 JSON 数据格式已迁移到 v4，新增按账号及 APNs 环境隔离的推送 token。
- PostgreSQL 16 已接管主存储，旧 JSON 会首次自动导入并保留不可覆盖的迁移前备份。
- 所有写操作使用数据库原子更新和版本冲突检测，JSON 继续作为滚动镜像供备份与回滚。
- 健康检查会验证数据库连接并报告当前存储后端；CI 使用真实 PostgreSQL 16 验证迁移和重启。

下一步：

- 多台 iPhone 的语音、云同步冲突和长距离路线容量验收。
- TestFlight 扩大内测后，将 PostgreSQL 单行 JSONB 状态逐步拆分为规范化业务表。

验收：

## 阶段 7：组队骑行增强

目标：让骑行小队在真实骑行中更容易保持队形并了解成员状态。

当前已完成：

- 骑行页可选择已加入的小队，主动开启或停止位置共享。
- 地图展示其他共享成员的昵称、最近位置和速度。
- 共享默认关闭，定位数据通过现有 HTTPS 鉴权接口传输。
- 服务端位置 90 秒自动过期，不写入 PostgreSQL；停止骑行、退出或解散小队时清除。
- 服务端接口、过期逻辑和 iOS 模拟器构建已通过自动化验证。
- 骑行地图提供醒目的 SOS 入口，选择小队后二次确认发送。
- SOS 自动刷新发送者临时位置，并通过 APNs 提醒其他成员。
- 接收方在 App 内可查看求助人和小队，并直接打开 Apple 地图定位。
- 小队状态面板展示实际参与共享的队友距离和位置更新时间。
- 队友距离超过 500 米并持续 45 秒时发送一次本地掉队提醒，回到 350 米内后恢复。
- 队友位置超过 60 秒未更新时发送一次失联提醒，恢复更新后允许再次提醒。
- 提醒开关保存在本机；地图标记和状态提示根据正常、掉队、失联状态变色。
- 小队创建者可把当前准确位置设为 6 小时有效的集合点，成员自动刷新地图标记、
  距离、设置人和到期时间，并通过 APNs 收到更新提醒。
- 设置集合点时可输入 40 字以内名称，骑行地图持续显示剩余直线距离，并可启动
  Apple 地图骑行导航。
- 骑手进入集合点 100 米范围并保持 10 秒后，本机发送一次到达提醒；离开 180 米后
  才允许重新触发，减少 GPS 漂移造成的重复提醒。
- 小队状态面板按成员展示集合点剩余距离、已到达或未共享本次位置状态。
- 骑行地图提供小队快捷语音入口，可直接发起呼叫、静音或结束当前语音。
- 可选择最近 8 条有轨迹的历史骑行作为参考路线，地图以蓝色虚线显示。
- 持续偏离参考路线 150 米超过 30 秒时提醒，回到 80 米内后自动恢复。

真机验收：

- 两台 iPhone 加入同一小队并开始骑行，双方地图能在约 15 秒内看到对方。
- 锁屏、前后台切换后位置仍能按系统授权情况更新。
- 停止共享或结束骑行后，对方地图上的位置在 90 秒内消失。
- 非小队成员不能读取或提交该小队位置。
- 一台 iPhone 发送 SOS 后，另一台能收到求助提醒并打开正确地图位置。
- 无准确 GPS 时不能发送；10 分钟内超过 3 次请求会被服务端限流。
- 两台设备持续共享时可看到队友距离；模拟超过 500 米 45 秒后只提醒一次。
- 关闭一台设备的位置共享后，另一台约 60 秒出现位置中断提醒。
- 队友恢复到 350 米内或恢复位置更新后，状态回到正常。
- 创建者设置集合点后，另一台 iPhone 收到推送并在约 15 秒内看到橙色旗标；普通成员
  不能修改或清除集合点。
- 创建者可输入集合点名称；成员点击导航能打开 Apple 地图并选择骑行路线。
- 成员在集合点 100 米内保持 10 秒后收到一次到达提醒，小队状态面板同步显示已到达。
- 从骑行地图发起小队语音，双方可接听并双向通话；地图上的静音和结束操作有效。
- 选择一条历史路线后能看到蓝色虚线；持续离开路线后仅提醒一次，回到路线附近后恢复。

下一步：

- 结合真实户外轨迹调整上报间隔、精度门槛和电量消耗。
- 增加集合点预计到达时间和队员到达进度汇总。
- 完成 App Store 截图、审核说明与崩溃日志收集。

## 阶段 8：账户与数据控制

目标：让用户直接查看权限、取得自己的数据并永久注销账户。

当前已完成：

- “我的”右上角新增账户与隐私设置。
- 展示定位、通知、麦克风和健康写入权限状态，并可跳转系统设置。
- App 内可打开隐私政策。
- 可导出账户资料、好友关系、小队和已同步骑行记录为 JSON，并调用系统分享面板。
- 永久注销使用二次确认；骑行未结束时禁止删除。
- 服务端在一次原子更新中清理账户、会话、好友、小队归属、骑行、推送 token 和语音邀请。
- 注销后清除本机骑行数据，并建立一个不含旧数据的新访客账户。
- 数据导出和账户删除接口已完成鉴权、隔离及持久化清理测试。

验收：

- 未登录请求导出或删除返回 `401`。
- 导出文件不包含 device hash、Bearer token 或 APNs token。
- 删除后旧会话立即失效，另一位用户不再看到被删除账号。
- 被删除账号创建的小队消失；其他人创建的小队保留且移除该成员。
- App 重启后不会恢复旧账户的骑行历史。
